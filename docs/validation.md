# 解析可能性の判定

本書を入力拒否条件の正式仕様とする。ランドマーク取得後も品質を検証し、不合格なら統計計算へ進まない。解析サービスの制御契約では、validation合格後にだけfeature extractionとstatisticsを呼ぶ。判定結果および失敗チェックの受け渡しは[解析サービス設計](analysis-service.md)を参照する。
以下の数値はすべて**MVP初期値**であり、実測検証で調整できる設定値として一元管理する。コードにマジックナンバーを散在させない。

## ファイルと参照群の検証

形式、デコード、バイト数、寸法、総ピクセル数を[非機能要件](non-functional-requirements.md)に従って検査する。未知の参照群IDは拒否し、既定の集団へ黙って置換しない。画像から年齢や性別を推定する処理は置かない。

## ハードリジェクトの初期閾値

`d(a,b)` は[画像解析](image-analysis.md)に定義した2次元ピクセル距離とする。

| 項目 | NG条件 | ユーザー向けの理由例 |
| --- | --- | --- |
| 顔なし | 検出0人 | 顔が見つかりません |
| 複数顔 | 検出2人以上 | 複数の顔が検出されました |
| 顔サイズ | Face Oval bbox幅 / 画像幅が0.30未満 | 顔が小さすぎます |
| 必須点の欠損 | 必須点が取得できない、有限でない、または画像外 | 計測に必要な顔の部分が写っていません |
| 画像端 | 必須点のいずれかが画像端から2%未満 | 顔が画像端に近すぎます |
| yaw | 絶対値が10度超 | 顔が横を向きすぎています |
| pitch | 絶対値が10度超 | 顔が上または下を向きすぎています |
| roll | 絶対値が5度超 | 顔が傾きすぎています |
| 口の開き | `d(13,14) / d(61,291) > 0.08` | 口を閉じた写真を使用してください |
| 目の開き | 左右いずれかのまぶた縦距離 / 眼幅が0.10未満 | 目を開けた写真を使用してください |

「未満」と「超」を区別し、境界値そのものは当該条件だけでは拒否しない。ただし黒つぶれ・白飛びの15%条件は15%以上で拒否する。外眼角幅0または非有限値は計測失敗として拒否する。異常に小さい外眼角幅の追加下限はMVPでは設けず、実画像検証で誤判定の有無を確認する。

## ランドマーク点集合

点番号を左右名称より優先する。MediaPipeの接続定義における左右は人物視点である。Face Landmarkerの478点構成を前提とする。

### 閉眼判定

| 対象 | 眼幅の2点 | 上まぶた | 下まぶた |
| --- | --- | --- | --- |
| 人物の右眼（接続定義 `RIGHT_EYE`） | 33, 133 | 159 | 145 |
| 人物の左眼（接続定義 `LEFT_EYE`） | 263, 362 | 386 | 374 |

各距離は`d`によるピクセル距離を使い、上・下まぶた点間距離を同じ眼の眼幅で割る。左右別々に評価し、どちらか一方でも比率が0.10未満なら拒否する。複数点の平均・最大値などの集約は行わない。この選択はMediaPipe Face Meshの眼輪郭接続に含まれる単一の上・下まぶた点を用いるMVP規約である。

### Face Oval bbox

Face Ovalの点集合は、MediaPipeの`FACEMESH_FACE_OVAL`接続の端点を重複除去した次の36点とする。

`10, 338, 297, 332, 284, 251, 389, 356, 454, 323, 361, 288, 397, 365, 379, 378, 400, 377, 152, 148, 176, 149, 150, 136, 172, 58, 132, 93, 234, 127, 162, 21, 54, 103, 67, 109`

各点の正規化`x`座標の最小値と最大値から`bbox_width = (max_x - min_x) * image_width`を求める。顔サイズ比は`bbox_width / image_width`、すなわち正規化x幅とする。顔高は現在のMVP判定に使わない。

### 必須点集合と画像端

validationの必須点集合は、スコア計測点、口開き点、閉眼点、およびFace Oval点の和集合とする。スコア計測点`{468, 473, 133, 362, 33, 263, 61, 291}`に、口開き判定点`{13, 14}`、閉眼判定点`{159, 145, 386, 374}`、上記Face Ovalの36点を加える。重複は1点として扱う。全点についてランドマーク配列内に存在し、x/yが有限で、`0 <= x <= 1`かつ`0 <= y <= 1`であることを要求する。

画像端判定は正規化座標で行う。必須点のいずれかについて`x < 0.02`、`x > 0.98`、`y < 0.02`、`y > 0.98`のいずれかなら拒否する。ちょうど0.02または0.98は「2%未満」ではないため、この条件だけでは拒否しない。目・口の判定点も必須点集合に含めるのは、当該部位の欠損・端切れを通過させないためである。

## 頭部姿勢

`output_facial_transformation_matrixes=True`で得る行列は、MediaPipe Face Geometryの定義上、静的canonical face modelから実行時faceへの写像であり、4x4の一様スケール・回転・平行移動を含み、最終行は`[0, 0, 0, 1]`である。行列なし、形状が4x4でない、非有限値、または回転部分を安定して正規化できない場合はvalidation失敗とする。姿勢検証を省略して通過させない。

行列はPython APIが返す4x4配列の行列として扱う。左上3x3 `A = M[0:3, 0:3]`を使い、一様スケール`s = cbrt(det(A))`を除いて`R = A / s`とする。`s`が有限かつ正であり、`R`が直交行列（`R.T @ R`が単位行列、許容誤差`1e-3`）であることを確認する。平行移動の最終列は角度算出に使わない。

Euler規約は行列座標のx軸まわりをpitch、y軸まわりをyaw、z軸まわりをrollとし、`R = Rz(roll) * Ry(yaw) * Rx(pitch)`（列ベクトル、右手系）に固定する。各軸の正方向はMediaPipeが定義する行列座標の右手系に従い、画面左右・上下への意味づけは実装時に既知姿勢画像で確認する。抽出式は`yaw=asin(clamp(-R[2,0], -1, 1))`、`pitch=atan2(R[2,1], R[2,2])`、`roll=atan2(R[1,0], R[0,0])`とする。各ラジアン値に`180 / pi`を掛けてdegreeへ変換し、既存閾値`abs(yaw)>10°`、`abs(pitch)>10°`、`abs(roll)>5°`を適用する。

`abs(cos(yaw)) <= 1e-6`のsingularity近傍ではEuler角が一意に定まらないため、姿勢計測失敗として拒否する。入力はimage_processingでEXIF方向を適用した画素であり、左右反転は行わない。したがって鏡像補正や角度符号の反転は加えない。MediaPipe行列のcanonical-to-runtime定義に従い、検証用の既知姿勢画像で軸・符号と実際のSDK出力の対応を実装時に確認する。

## Face Landmarker confidence

採用中のPython Tasks APIの静止画像`FaceLandmarkerResult`には顔ごとのdetection confidenceまたはface presence confidenceの公開フィールドがない。`min_face_detection_confidence=0.7`と`min_face_presence_confidence=0.7`はFaceLandmarker生成時の検出・presence閾値として適用される。validation層でconfidenceを再取得・再判定しない。閾値に満たず結果に顔が含まれない場合は`face_count == 0`として扱い、confidence不足を顔なしと別理由に区別しない。Blendshape等をconfidenceの代用にしない。

## 画質チェックの初期閾値

評価対象は顔領域ではなく、デコード後の画像全体とする。画質評価専用に、縦横比を維持して長辺が512pxになるよう縮小する。長辺が512px以下なら拡大しない。出力幅・高さは元寸法に対する倍率を乗じ、最も近い正整数（0.5は切り上げ）とし、最低1pxとする。縮小補間はOpenCV `INTER_AREA`相当とする。

RGB画像をOpenCV `COLOR_RGB2GRAY`相当の係数で8bitグレースケールへ変換する。Laplacianはカーネルサイズ3、出力深度`CV_64F`（64bit浮動小数点）で計算し、その配列の分散を使う。平均輝度と画素率は8bitグレースケール画像から計算し、黒つぶれ率は値0〜5、白飛び率は250〜255の画素数を総画素数で割った割合とする。

| 項目 | NG条件 | 理由例 |
| --- | --- | --- |
| ぼけ | Laplacian varianceが80未満 | 画像がぼやけています |
| 暗すぎる | 平均輝度40未満 | 画像が暗すぎます |
| 明るすぎる | 平均輝度215超 | 画像が明るすぎます |
| 黒つぶれ | 画素値0〜5が15%以上 | 画像の暗い部分がつぶれています |
| 白飛び | 画素値250〜255が15%以上 | 画像に白飛びがあります |

画質用縮小画像はランドマーク処理用画像と別の一時配列であり、ランドマーク座標や解析寸法を置き換えない。閾値はMVP初期値であり、理論だけでは誤拒否率を決められない。実画像20〜30枚以上（異なる解像度、照明、ぼけ、露出を含む）で誤拒否・見逃しを確認し、必要なら一元管理された設定値を調整する。この検証項目は実画像評価のTODOとして残す。

## 遮蔽と限界

欠け判定は採用計測点とFace Oval点を基準とし、単純に額や顎の輪郭全点が写っていることをスコア算出条件にしない。マスク、手、髪、眼鏡などによる遮蔽も検証画像に含める。遮蔽を確実に検出できるとは仮定せず、入力ガイドと品質判定の限界を明示する。MVPに高度な遮蔽推定や機械学習ベース品質判定を追加しない。

## エラー契約

期待される入力不合格をHTTP内部エラーだけで返さず、安定したvalidation結果コードと日本語の再入力理由を持たせる。例えば顔サイズ不足、横向き、複数顔を別コードにする。コード名、複数不合格時の表示順序、HTTPステータスの対応表はWeb・解析サービス実装時に定めるTODOであり、本書ではHTTPステータスやWeb表示仕様を定義しない。スコアの代わりに0点を返して成功に見せない。

不正ファイル、品質不合格、統計モデルの不備、想定外の内部障害を区別する。内部障害の詳細やスタックトレースを画面へ露出せず、request idで調査できるようにする。正常終了、不合格、例外のいずれでも画像の破棄を行う。

## 公式定義

- Face Oval、左右の眼輪郭接続: [MediaPipe Python FaceLandmarksConnections](https://developers.google.com/edge/api/mediapipe/python/mp/tasks/vision/FaceLandmarksConnections)
- transformation matrixがcanonical faceからruntime faceへの写像で、scale・rotation・translationを含む4x4である定義: [MediaPipe face_geometry.proto](https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/modules/face_geometry/protos/face_geometry.proto)
- Python Face Landmarkerの公開結果型と設定: [MediaPipe Face Landmarker Python API](https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/tasks/python/vision/face_landmarker.py)

## Issueコード

内部CheckResultのname、value、thresholdはサーバーログ用であり、APIでは安定したissue codeと日本語messageへ変換する。同時に判断できる問題は複数返す。顔未検出では顔依存チェックを抑止し、`FACE_NOT_FOUND`を主要理由とする。必須点不足は内部でIDを記録し、利用者には目・口・顔輪郭など部位名を示す。
