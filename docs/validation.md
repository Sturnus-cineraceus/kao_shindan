# 解析可能性の判定

本書を入力拒否条件の正式仕様とする。
ランドマーク取得後も品質を検証し、不合格なら統計計算へ進まない。
解析サービスの制御契約では、validation合格後にだけfeature extractionとstatisticsを呼ぶ。判定結果および失敗チェックの受け渡しは[解析サービス設計](analysis-service.md)を参照する。
以下の数値はすべて**MVP初期値**であり、実測検証で調整できる設定値として一元管理する。
コードにマジックナンバーを散在させない。

## ファイルと参照群の検証

形式、デコード、バイト数、寸法、総ピクセル数を[非機能要件](non-functional-requirements.md)に従って検査する。
未知の参照群IDは拒否し、既定の集団へ黙って置換しない。
画像から年齢や性別を推定する処理は置かない。

## ハードリジェクトの初期閾値

`d(a,b)` は[画像解析](image-analysis.md)に定義した2次元ピクセル距離とする。

| 項目 | NG条件 | ユーザー向けの理由例 |
| --- | --- | --- |
| 顔なし | 検出0人 | 顔が見つかりません |
| 複数顔 | 検出2人以上 | 複数の顔が検出されました |
| 検出confidence | 0.7未満 | 顔をはっきり写した写真を使用してください |
| face presence confidence | 0.7未満 | 顔をはっきり写した写真を使用してください |
| 顔サイズ | Face Oval bbox幅 / 画像幅が0.30未満 | 顔が小さすぎます |
| 必須点の欠損 | 必須点が取得できない、または画像外 | 計測に必要な顔の部分が写っていません |
| 画像端 | 必須点が画像端から2%未満 | 顔が画像端に近すぎます |
| yaw | 絶対値が10度超 | 顔が横を向きすぎています |
| pitch | 絶対値が10度超 | 顔が上または下を向きすぎています |
| roll | 絶対値が5度超 | 顔が傾きすぎています |
| 口の開き | `d(13,14) / d(61,291) > 0.08` | 口を閉じた写真を使用してください |
| 目の開き | 左右いずれかのまぶた縦距離 / 眼幅が0.10未満 | 目を開けた写真を使用してください |

「未満」と「超」を区別し、境界値そのものは当該条件だけでは拒否しない。
外眼角幅0または異常に小さい場合も計測失敗として拒否する。
異常に小さいとする数値は未決定のためTODOとする。

欠け判定は採用計測点を基準とし、単純に額や顎の輪郭の全点が写っていることをスコア算出の条件にしない。
マスク、手、髪、眼鏡などによる遮蔽も検証画像に含める。
遮蔽を確実に検出できるとは仮定せず、入力ガイドと品質判定の限界を明示する。

## 頭部姿勢と点集合の要検証事項

頭部角度はfacial transformation matrixから算出する。
座標軸、回転順序、符号、鏡像時の扱いは既知姿勢画像による単体テストで固定する。
行列が取得できない場合は姿勢検証を省略して通過させない。

次は具体的な定義が未決定のため、実装開始時に固定する必要がある。

- 閉眼判定に使う上下まぶたの点番号と、複数点なら集約方法。
- 品質判定を含む必須点集合とFace Oval bboxの構成点。
- 2%余白の具体化（暫定案：左右端は画像幅、上下端は画像高さで正規化）。
- confidenceの取得方法と低信頼時の理由分離。

SDKの[公式設定](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/python)で検出とpresenceの閾値を設定する。
結果からconfidenceを別途取得できるかは採用SDKで要検証とし、存在しない結果フィールドを前提にしない。
内部で検出が抑制されて0顔になった場合、信頼度不足と顔なしを区別できるとは限らない。

## 画質チェックの初期閾値

長辺512pxへ縮小した8bitグレースケール画像で評価する。

| 項目 | NG条件 | 理由例 |
| --- | --- | --- |
| ぼけ | Laplacian varianceが80未満 | 画像がぼやけています |
| 暗すぎる | 平均輝度40未満 | 画像が暗すぎます |
| 明るすぎる | 平均輝度215超 | 画像が明るすぎます |
| 黒つぶれ | 画素値0〜5が15%以上 | 画像の暗い部分がつぶれています |
| 白飛び | 画素値250〜255が15%以上 | 画像に白飛びがあります |

15%ちょうどは拒否する。
これらは計測理論の定数ではなく初期運用値である。
20〜30枚以上の条件を変えた写真で誤拒否率を確認する。

評価範囲（画像全体か顔領域か）、512px未満の画像の扱い、グレースケール変換、縮小補間、Laplacianのカーネルと出力型は要検証である。
暫定の実装案は画像全体を評価し、小さい画像を拡大しない方式とするが、採用前に閾値との整合を確認する。
解析用画像の上限サイズと、この画質評価専用の縮小画像を混同しない。

## エラー契約

期待される入力不合格をHTTP内部エラーだけで返さず、安定したvalidation結果コードと日本語の再入力理由を持たせる。
例えば顔サイズ不足、横向き、複数顔を別コードにする。
コード名、複数不合格時の表示順序、HTTPステータスの対応表はTODOである。
スコアの代わりに0点を返して成功に見せない。

不正ファイル、品質不合格、統計モデルの不備、想定外の内部障害を区別する。
内部障害の詳細やスタックトレースを画面へ露出せず、request idで調査できるようにする。
正常終了、不合格、例外のいずれでも画像の破棄を行う。
