# 画像解析と特徴抽出

本書を画像座標と計測点の正式仕様とする。
品質閾値は[validation.md](validation.md)、特徴ベクトルの順序と統計は[statistics.md](statistics.md)に置く。

## MediaPipe Face Landmarker

静止画像モードを使用する。公式配布のFace Landmarker float16、モデルディレクトリ版 `1` を採用する。
識別子は `face_landmarker/face_landmarker/float16/1/face_landmarker.task`、モデルURLは[公式配布物](https://storage.googleapis.com/mediapipe-models/face_landmarker/face_landmarker/float16/1/face_landmarker.task)である。
Docker build時に `/opt/kao-cal/models/face_landmarker.task` へ取得し、SHA-256 `64184e229b263107bc2b804c6625db1341ff2bb731874b0bcc2fe6544e0bc9ff` を確認する。取得処理は `scripts/download_face_landmarker.py` に置き、モデル本体はGit管理しない。
採用モデルは478点を含む構成で、468と473を含む必須点集合を内部型に保持する。
初期設定は次とする。

| 設定 | 値 | 目的 |
| --- | --- | --- |
| `running_mode` | `IMAGE` | 静止画像の解析 |
| `num_faces` | `2` | 複数顔を検出して拒否する |
| `output_facial_transformation_matrixes` | `true` | 頭部姿勢の検査 |
| `min_face_detection_confidence` | `0.7` | 低信頼検出を抑制 |
| `min_face_presence_confidence` | `0.7` | 顔存在の信頼度を制限 |

`num_faces` は検出上限であり、2顔を検出したら複数人として拒否する。
画像中の顔数を無制限に数える仕様ではない。
Python SDKの設定名と動作は[公式ガイド](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/python)で確認する。
Pythonは3.12.9、MediaPipe Python SDKは `0.10.21` に固定する。モデルの実推論スモークテストと変換アダプターの単体テストを行う。

## 人類学的計測点との対応

| 産総研項目 | MediaPipe点番号 | 写真上の対応 | MVP用途 |
| --- | --- | --- | --- |
| 瞳孔間幅 | 468 ↔ 473 | 左右iris中心 | 比率の分子 |
| 内眼角幅 | 133 ↔ 362 | 左右内眼角 | 比率の分子 |
| 外眼角幅 | 33 ↔ 263 | 左右外眼角 | 共通分母 |
| 口裂幅 | 61 ↔ 291 | 左右口角 | 比率の分子 |

これをMVP採用点とする。
左右名称の差は2点間距離を変えないが、表示時の鏡像と点番号の対応は検証する。
iris中心は瞳孔中心の代理点であり、人類学的計測点との厳密な一致が保証されるわけではない。
産総研の計測定義図と写真の点位置を照合し、視線や眼鏡による誤差を確認する。

下顎角幅、鼻高、鼻下・オトガイ距離はスコアから除外する。
形態学顔高と頬弓幅の比は、実測点と表面ランドマークの差を考慮し、実験的な追加特徴として扱う。
Face Ovalやまぶた、唇の点は品質判定に利用できるが、それ自体をスコア特徴へ追加しない。
部位のピクセル単位セグメンテーションはMVPで必要としない。

### 追加特徴の診断

形態学顔高 / 頬弓幅に対応する `face_aspect_ratio` は任意の実験的追加特徴である。core3は常時使用する。
瞳孔間幅、内眼角幅、外眼角幅、口裂幅をそれぞれ頬幅で割った4特徴も選択できる。分子にはcore3と同じ計測距離を再利用し、分母には234 ↔ 454を使う。追加特徴を選択したときに234と454を必須とし、顔の縦横比の選択時にはさらに168と152を必須とする。
横幅の代理点候補は234 ↔ 454と127 ↔ 356、顔高の代理点候補は168 ↔ 152と6 ↔ 152である。
これらは診断目的の仮説であり、zygion、sellion、gnathionなどの人類学的計測点と同一とは扱わない。
`python scripts/inspect_face_ratio_candidates.py <画像>` はvalidation後のroll補正済み座標から距離と全組み合わせの比率を表示し、元画像の検出点と線を `tmp/face-ratio-diagnostics/` に重ねて保存する。
モデルのパスは `--model`、出力先は `--output` で変更できる。
この診断はWeb解析や統計計算から呼ばれない。

正式採用には、複数画像での計測位置の目視確認、姿勢や表情による変動の確認、候補ペア間の比較、AIST計測定義との意味的なずれの確認を少なくとも必要とする。
初期実験版はroll補正後の解析用座標で `pixel_distance(168, 152) / pixel_distance(234, 454)` を使う。非正方形画像でもピクセル座標で距離を求める。これらはAISTの計測点そのものではなく、対応させる写真上の代理点であり、人類学的計測点との一致は保証しない。選択時だけ4点を必須とする。

## 前処理と座標系

安全な画像受理条件は[非機能要件](non-functional-requirements.md)に従う。
EXIFは解析前に除去し、寸法、ランドマーク、計測線が同じ向きの画像を参照するようにする。
Orientationの適用順序、透過PNGの背景色、色変換と補間方法はTODOとし、再現性のため設定と処理順を固定する。
リサイズする場合は縦横比を維持する。

画像幅 $W$、高さ $H$ は、ランドマーク抽出に実際に渡した画像の寸法である。
MediaPipeのnormalized coordinatesでは、$x$ は画像幅、$y$ は画像高さで正規化される。
2点間の距離は次のようにピクセル尺度へ戻して計算する。

$$
d_{px}=\sqrt{((x_2-x_1)W)^2+((y_2-y_1)H)^2}
$$

**normalized coordinateのxとyをそのままユークリッド距離へ入れてはいけない。**
非正方形画像では縦横の尺度が異なり、距離と比率が歪むためである。
例えば $W=800$、$H=400$、座標差がともに0.1なら、距離は $\sqrt{80^2+40^2}$ pxとなる。
3次元のz値をmmとして扱わず、MVPの距離は2次元のxとyだけから求める。

画像が縮小済みなら縮小後の寸法を使用し、元寸法と混在させない。
重畳表示でも同じ画像と座標変換を使う。
元画像への再投影が必要なら変換を明示する。

## 比率生成と限界

4寸法を同一画像から得て、外眼角幅で各分子を割る。
分母0、欠損点、非有限値を計測失敗として停止する。
実装では座標・距離・比率の非有限値と0以下の外眼角幅を拒否する。
異常に小さい外眼角幅を数値で区切る追加閾値はMVPでは設けず、必要性はvalidationの実画像検証で確認する。
浮動小数点演算で有限な比率を生成できない場合も計測失敗とする。
比率化で等倍率の拡大縮小の影響を除けるが、遠近歪み、広角歪み、姿勢、表情、視線による誤差は残る。
単写真からの実寸mmや姿勢補正後の3D寸法は推定しない。

品質判定の必須点集合、閉眼判定の点、行列からの角度算出規約は[validation.md](validation.md)を正本とする。
実装時に正方形と非正方形画像、等倍率変換、既知姿勢画像で[テスト](testing.md)し、とくに姿勢角の軸・符号と実SDK出力の対応を確認する。
